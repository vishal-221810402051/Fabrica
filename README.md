# Fabricgamma Microfluidic Design Platform

Fabricgamma is a planned AI-powered platform for designing microfluidic chips with an authoritative engineering model, deterministic validation, deterministic calculations, and production CAD export.

Current status: Phase 3 browser-local project management foundation. The repository contains the Phase 1 monorepo foundation, the Phase 2 versioned project model and unit system, and Phase 3 web infrastructure for local project state, IndexedDB persistence, JSON import/export, autosave, recovery, recent projects, and undo/redo.

## Purpose

The platform is intended to support future workflows for:

- Node-based microfluidic design editing.
- Property editing with explicit engineering units.
- Deterministic calculations and validation.
- 2D layout and 3D preview derived from the same project model.
- CAD job orchestration and STEP/STL export.
- AI-assisted structured proposals that are validated before they affect a project.
- Persistence, audit metadata, and reproducible derived artifacts.

## Architecture Principles

The versioned project model is the engineering source of truth. Future editors, layouts, previews, calculations, validation engines, AI orchestration, CAD generation, export, and persistence must consume the same authoritative model or reproducible derived data. Conflicting engineering copies must not be maintained.

Internal engineering units are locked as:

- Length: millimetres, mm
- Area: square millimetres, mm²
- Volume: cubic millimetres, mm³
- Time: seconds, s
- Pressure: pascals, Pa
- Volumetric flow: mm³/s
- Temperature: degrees Celsius, °C
- Angle: radians

The exact identity is:

1 µL = 1 mm³

Display-unit conversion belongs at presentation and input/output boundaries. Display-unit choices must not mutate canonical internal values, and units must never be inferred from unlabeled numbers.

## AI Trust Boundary

GPT output is untrusted structured input. GPT may propose project-model commands or patches, but those proposals must pass schema validation, version compatibility checks, unit validation, semantic validation, stable-identifier validation, authorization checks, engineering-rule validation, and applicable manufacturing/material profile validation before affecting the authoritative project model.

GPT must not directly mutate persistence, bypass deterministic engines, mark a design Engineering Ready, fabricate engineering limits, or execute arbitrary CAD or shell code.

## Visualization And CAD Authority

React Three Fiber and Three.js are visualization systems. They may present preview geometry, but they are not the production CAD authority.

Production STEP geometry must be generated by the approved B-representation CAD backend. CadQuery is the approved initial backend, with OpenCascade output authoritative for production STEP geometry. Rendering, meshing, or exporting a design does not by itself prove that the design is Engineering Ready.

## Planned Technical Baseline

- Frontend: React, TypeScript, Vite, Tailwind CSS, React Flow, Zustand, React Three Fiber, Zod, Vitest, Playwright.
- Backend: Python 3.12, FastAPI, Pydantic, SQLAlchemy, Alembic, PostgreSQL, Pytest.
- CAD: Python, CadQuery, OpenCascade, STEP export, STL export.
- Infrastructure: Git, GitHub, GitHub Actions, Docker Compose, ESLint, Prettier, Ruff, Pyright, Conventional Commits.
- JavaScript package manager: pnpm.
- Python dependency and virtual-environment manager: uv.

Phase 3 adds browser-local persistence only. It does not implement backend persistence, engineering calculations, manufacturing rules, GPT integration, production CAD, STEP/STL export, simulation, or Engineering Ready workflows.
